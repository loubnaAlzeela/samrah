# سمرة | Samrah

تطبيق جوال لألعاب الورق الجماعية أونلاين، بهوية بصرية خاصة به. **لا شيء منسوخ من جواكر** (لا رسومات، ولا أيقونات، ولا نصوص). اسم المجلد والحزم (`lamma`) قديم، واسم المنتج **سمرة / Samrah**.

المرحلة الحالية (أ) بلا حسابات: الاسم والمستوى والعملات محلية على الجهاز وللعرض فقط.

## الألعاب

| طرنيب سوري 41 | 4، كل لاعب يطلب لنفسه | [tarneeb-syrian-41.md](docs/rules/tarneeb-syrian-41.md) |

كل ملف قواعد فيه قسم «قرارات معتمدة» يوضّح ما اخترناه حيث سكتت القوانين.

## هيكل المشروع

| المجلد | الدور |
|---|---|
| `packages/rules` | محرّك القواعد بلغة TypeScript: دوال بحتة بلا إدخال وإخراج (التوزيع، والمزايدة، واللعب، والحساب، وما يراه كل لاعب، ولعب الحاسوب، وإعدادات الغرفة، وفلتر الدردشة)، مع اختبارات vitest. |
| `apps/server` | سيرفر اللعب: Node مع Colyseus 0.18. السيرفر هو المرجع الوحيد، والخلط بـ`crypto.randomInt`. معه اختبارات تكامل بسيرفر حقيقي وعملاء حقيقيين. |
| `apps/mobile` | تطبيق Flutter (أندرويد، وiOS لاحقًا): كل الألعاب، ولعب الورق بالسحب، والحركات، والمؤثرات الصوتية ونطق الخيارات. التفاصيل في [README الجوال](apps/mobile/README.md). |
| `docs/rules` | قواعد كل لعبة كما يطبّقها المحرّك، مع أمثلة محلولة. |
| `scripts` | `e2e.mts` (اختبار شامل بعدة عملاء حقيقيين) و`bots.mts` (يملأ مقاعد غرفة بعملاء بوت للتجربة). |
| `design` | ملفات التصميم المرجعية. |

### إخفاء الورق
يستلم كل لاعب رسالة `state` مبنية له وحده: يده، وعدد أوراق الآخرين، والمعلومات العامة فقط. لا توجد حالة مشتركة تحمل أيادي اللاعبين، والاختبارات تتحقق من أن الرسائل لا تسرّب ورق الآخرين ولا الورق غير الموزّع.

## التشغيل المحلي

المتطلبات: Node 24 وnpm 11، وFlutter للتطبيق.

```bash
npm install
npm run dev:server     # سيرفر اللعب على ws://localhost:2567
```

ثم التطبيق (من `apps/mobile`)، مع عنوان السيرفر:

```bash
flutter run --dart-define=GAME_SERVER=ws://<عنوان-الجهاز-على-الشبكة>:2567
flutter build apk --release --dart-define=GAME_SERVER=ws://<عنوان-الجهاز-على-الشبكة>:2567
```

محاكي أندرويد يصل إلى الجهاز على `ws://10.0.2.2:2567` (العنوان الافتراضي). أما الهاتف الحقيقي فيحتاج عنوان الجهاز على الشبكة المحلية (`ipconfig`).

للتجربة وحدك: افتح غرفة واضغط «ابدأ اللعبة»، فتمتلئ المقاعد بالحاسوب. أو أدخل عملاء بوت حقيقيين إلى الغرفة نفسها:
```bash
npx tsx scripts/bots.mts <CODE> 3
```

### الاختبارات

```bash
npm test                        # اختبارات القواعد (vitest)
npm -w @lamma/server run test   # اختبارات تكامل السيرفر
npm run typecheck               # فحص الأنواع للقواعد والسيرفر
cd apps/mobile && flutter test  # اختبارات التطبيق
```

اختبار end-to-end (عدة عملاء WebSocket حقيقيين، ويفحص كل رسالة شبكة خام):
```bash
# طرفية 1: سيرفر بمهل قصيرة لتسريع الاختبار
LAMMA_TRICK_PAUSE_MS=30 LAMMA_HAND_PAUSE_MS=60 LAMMA_RECONNECT_SECONDS=2 LAMMA_TURN_SECONDS=3 LAMMA_AUTO_MOVE_MS=40 LAMMA_QUICK_FILL_MS=1500 npx tsx apps/server/src/index.ts
# طرفية 2
npm run e2e
```

## إعدادات السيرفر (متغيرات البيئة)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | 2567 | منفذ سيرفر اللعب |
| `LAMMA_RECONNECT_SECONDS` | 90 | مدة حجز مقعد اللاعب المنقطع قبل أن يلعب عنه الحاسوب |
| `LAMMA_TURN_SECONDS` | (من سرعة الغرفة) | تجاوز اختباري لمهلة كل حركة؛ عادةً تُقرأ من سرعة الغرفة (45 / 30 / 15) |
| `LAMMA_AUTO_MOVE_MS` | 900 | تأخير حركة الحاسوب |
| `LAMMA_TRICK_PAUSE_MS` | 1200 | مدة بقاء الأكلة مكشوفة قبل جمعها |
| `LAMMA_HAND_PAUSE_MS` | 5000 | مدة شاشة نتيجة الجولة |
| `LAMMA_QUICK_FILL_MS` | 20000 | مهلة «العب الآن» قبل أن تمتلئ الطاولة العامة بالحاسوب |

متغيرات `LAMMA_*` القصيرة للاختبار فقط؛ التشغيل العادي (`npm start -w @lamma/server`) يستعمل القيم الافتراضية.

## النشر

`Dockerfile` في جذر المشروع يبني صورة السيرفر وحده (القواعد والسيرفر فقط)، وتستعمله Railway وغيرها تلقائيًا. المنفذ يُقرأ من `PORT`.

**المنشور حاليًا:** على Railway (منطقة EU West)، ويُنشر تلقائيًا مع كل رفع إلى `main`. العنوان `wss://samrah-production.up.railway.app`، والمتغير `PORT=2567` مضبوط هناك (الرابط العام موجَّه إلى هذا المنفذ). نسخة التطبيق للهواتف:

```bash
flutter build apk --release --dart-define=GAME_SERVER=wss://samrah-production.up.railway.app
```

سيرفر اللعب عملية Node دائمة تحتفظ باتصالات WebSocket (`npm start -w @lamma/server`)، فلا تصلح له استضافات الدوال (serverless). الغرف محفوظة في الذاكرة، فالمطلوب نسخة واحدة، وأي إعادة تشغيل تقطع المباريات الجارية. التطبيق المنشور يحتاج عنوانًا آمنًا: `GAME_SERVER=wss://<النطاق>`.

## الرمز السري وإعادة الاتصال

- أول دخول للغرفة يعطي التطبيق رمزًا سريًا للمقعد.
- إذا انقطع اللاعب: المقعد محجوز 90 ثانية، والباقون يرون «بانتظار فلان…». الدخول بالرمز نفسه يعيده إلى مقعده وورقه.
- إذا لم يرجع خلال المهلة: يكمل الحاسوب عنه حتى النهاية، ويستعيد مقعده فور عودته. قبل بداية اللعب يتحرّر المقعد.
- لكل حركة مهلة (من سرعة الغرفة)، وبعدها يلعب الحاسوب حركة واحدة. بعد 3 مرات متتالية يكمل الحاسوب حتى يلمس اللاعب الشاشة أو يلعب.
- فتح المقعد نفسه من جهاز آخر ينقل الجلسة إليه ويغلق القديمة.
- **الإخراج:** قبل البدء فوري. وأثناء اللعب يكمل اللاعب الجولة الحالية ثم يُخرج، ويأخذ مقعده الحاسوب.
