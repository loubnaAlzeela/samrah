# لَمّة | LAMMA

منصة ألعاب ورق جماعية أونلاين، بهيكل كلاسيكي كامل (نمط جواكر) بهوية بصرية خاصة. **لا شيء من جواكر منسوخ** (لا رسومات، لا أيقونات، لا نصوص) — كل الأيقونات مرسومة، والألوان والخطوط من `design/tokens.css`.

الموقع حالياً للمعاينة؛ المنتج النهائي تطبيق موبايل (التغليف بـCapacitor مرحلة لاحقة بانتظار الموافقة). المرحلة الحالية (أ) بلا حسابات: الاسم والمستوى والعملات كلها محلية على الجهاز وللعرض فقط.

## الـStack (معتمد)

TypeScript monorepo (npm workspaces):

| المجلد | الدور |
|---|---|
| `packages/rules` | محرّك القواعد: دوال بحتة بلا I/O (توزيع، مزايدة، لعب، حساب، فلترة العرض لكل لاعب، الطيار الآلي، إعدادات الغرفة، فلتر الدردشة) + اختبارات vitest. طرنيب عادي وطرنيب سوري 41. |
| `apps/server` | سيرفر اللعب: Node + Colyseus 0.18 (`@colyseus/core` + `@colyseus/ws-transport`). السيرفر هو المرجع الوحيد؛ الخلط بـ`crypto.randomInt`. + اختبارات تكامل (`apps/server/test`) بسيرفر حقيقي وعملاء SDK حقيقيين. |
| `apps/web` | الواجهة: React 19 + Vite 8، عربي RTL، موبايل أولاً، والستايل كله من `design/tokens.css`. الشاشات كلها مرسومة على «لوحة» ثابتة 390×797 (`components/Stage.tsx`) بإحداثيات المصمم، وتتصغّر لتدخل أي شاشة. |
| `docs/rules` | وثائق القواعد مع أمثلة محلولة وقسم «قرارات معتمدة». |
| `scripts` | `e2e.mts` (اختبار شامل بعدة عملاء حقيقيين، 5 مراحل) و`bots.mts` (أداة تجربة: تملأ المقاعد الفاضية بعملاء بوت حقيقيين — غير الطيار الآلي والكمبيوتر). |
| `design` | ملفات المصمم (لا يعدّلها المبرمج): `tokens.css`، و`layout-v2.md/html` (الطاولة/اليد/النافذة الوسطية)، و`layout-v3.md/html` (الهيكل الكامل: الرئيسية، الغرفة، اختيار الشريك، لائحة الطاولات، الألعاب/المتجر/الأندية/التحديات، الشريط السفلي). |

### إخفاء الورق
كل عميل يستلم رسالة `state` مبنية له وحده بالدالة `viewFor(state, seat)`: يده هو + عدد أوراق الباقين + المعلومات العامة فقط. ما في أي `schema state` مشترك يحمل الأيادي. الفلترة دالة بحتة مختبرة بـvitest، والـe2e يفحص كل رسالة شبكة خام (بايتات) للتأكد إنه ما في تسريب.

## الميزات (المرحلة أ)

- **طرنيب** و**طرنيب سوري 41**، بمزايدة ولعب وحساب كاملين.
- **إنشاء غرفة** بإعدادات: خاصة (كود+رابط) أو عامة (تظهر بلائحة لحظية)، دردشة on/off، إخراج اللاعبين on/off، بدون مغادرة، سرعة الدور (هادئة 45 / عادية 30 / سريعة 15 ثانية)، النتيجة 31/41/61 (السوري ثابت 41)، وتصنيف اللعبة (أدنى مستوى دخول 1–10، يُخزَّن ويُعرض بس، الفرض الفعلي بعد الحسابات).
- **بدء مع الكمبيوتر:** صاحب الغرفة يبدأ قبل اكتمال 4، والمقاعد الفاضية تصير لاعبين كمبيوتر (أسماء عربية، نفس منطق الطيار الآلي). إنسان يدخل بعدين بالرابط أو من اللائحة العامة ياخذ مقعد كمبيوتر بين اللمّات.
- **اختيار الشريك:** قبل البدء، صاحب الغرفة (أو أول لاعب جالس) يختار شريكه من الجالسين.
- **لعبة ودية / العب الآن:** ينضم لأول طاولة عامة فيها مكان لنفس اللعبة، وإلا يفتح طاولة عامة جديدة تُعبّى بالكمبيوتر تلقائياً بعد 20 ثانية.
- **لائحة الطاولات العامة:** لحظية عبر غرفة lobby من Colyseus (`enableRealtimeListing`)، تعرض الإعدادات والمقاعد وحالة اللعبة.
- **الإخراج:** قبل البدء فوري؛ أثناء اللعب **يُحجز لنهاية الجولة الحالية** ومقعد المُخرَج يروح لكمبيوتر.
- **دردشة نصية** بالطاولة: فقاعات فوق الأفاتار (4 ثوانٍ) + سجل + رسائل جاهزة، حد 120 حرف، تقييد معدّل 1.5 ثانية بين رسائل اللاعب الواحد، فلتر كلمات بسيط، وكتم لاعب محلي (بالجهاز، ما يوصل للسيرفر).
- **مؤقت الدور** والطيار الآلي والانقطاع وإعادة الاتصال: كما بالشريحة 2 (حلقة حول الأفاتار، 3 مرات متتالية بلا حركة ← طيار آلي، رجوع فوري بالتوكن أو باللمس).
- **الشريط السفلي (5 تبويبات):** الرئيسية والألعاب شغّالتان، والمتجر/الأندية/التحديات عرض فقط (المرحلة ب: حسابات، عملات حقيقية، مستويات).
- **صوت اللعبة:** نغمات قصيرة مولّدة بـWeb Audio API (لا ملفات صوتية، لا مكتبات مرخّصة) لتوزيع الورق، لعب ورقة، الفوز باللمّة، طلبك/تمريرك بالمزايدة، تحذير آخر 5 ثواني، وفوز/خسارة اللعبة. أيقونة السماعة أعلى يسار الطاولة تكتم/تشغّل فعلياً (تُخزَّن محلياً). الصوت شغّال افتراضياً، وأول لمسة بالتطبيق تكفي لتفعيله (قيد المتصفحات).

## التشغيل المحلي

المتطلبات: Node 24 (مجرّب على 24.16) و npm 11.

```bash
npm install
npm run dev:server     # سيرفر اللعب على ws://localhost:2567
npm run dev:web        # الواجهة على http://localhost:5173
```

افتح http://localhost:5173، اكتب اسمك، واختار طرنيب أو طرنيب سوري 41. «إنشاء لعبة» يفتح نافذة الإعدادات، و«لعبة ودية» تدخلك بأسرع طاولة عامة متوفرة.

للتجربة لحالك: افتح غرفة واضغط «بدء اللعبة» (تتعبّى بالكمبيوتر تلقائياً)، أو شغّل عملاء بوت حقيقيين يدخلون نفس الغرفة:
```bash
npx tsx scripts/bots.mts <CODE> 3
```

### الاختبارات

```bash
npm test                        # اختبارات القواعد (vitest)، ~40-60 ثانية
npm -w @lamma/server run test   # اختبارات تكامل السيرفر (سيرفر حقيقي + عملاء SDK حقيقيين)
npm -w @lamma/web run test      # اختبارات وحدة (منطق توليد الصوت — بيانات بحتة، بلا AudioContext حقيقي)
npm run typecheck               # tsc للحزم كلها
```

اختبار end-to-end (عدة عملاء WebSocket حقيقيين، 5 مراحل: لعبة كاملة وانقطاع قصير؛ غياب > مهلة الحجز والطيار الآلي يكمل للنهاية؛ مؤقت الدور والتحويل للطيار الآلي بعد 3 مرات؛ غرفة عامة يبدأها المضيف مع كمبيوتر ولاعب متأخر ياخذ مقعد كمبيوتر بين اللمّات؛ الدردشة مع التقييد. وفحص كل رسالة شبكة خام):
```bash
# طرفية 1: سيرفر بمهل قصيرة لتسريع الاختبار
LAMMA_TRICK_PAUSE_MS=30 LAMMA_HAND_PAUSE_MS=60 LAMMA_RECONNECT_SECONDS=2 LAMMA_TURN_SECONDS=3 LAMMA_AUTO_MOVE_MS=40 LAMMA_QUICK_FILL_MS=1500 npx tsx apps/server/src/index.ts
# طرفية 2
npm run e2e
# الطرنيب السوري:
LAMMA_E2E_VARIANT=syrian41 npm run e2e
```

## الإعدادات (متغيرات البيئة)

| المتغير | أين | الافتراضي | الوصف |
|---|---|---|---|
| `PORT` | server | 2567 | منفذ سيرفر اللعب |
| `LAMMA_RECONNECT_SECONDS` | server | 90 | مدة حجز مقعد اللاعب المنقطع قبل ما ياخده الطيار الآلي |
| `LAMMA_TURN_SECONDS` | server | (من سرعة الغرفة) | تجاوز اختباري لمهلة كل حركة؛ عادة تُقرأ من إعداد سرعة الغرفة (45/30/15) |
| `LAMMA_AUTO_MOVE_MS` | server | 900 | تأخير حركة الطيار الآلي أو الكمبيوتر |
| `LAMMA_TRICK_PAUSE_MS` | server | 1200 | مدة بقاء الأكلة مكشوفة قبل جمعها |
| `LAMMA_HAND_PAUSE_MS` | server | 5000 | مدة شاشة نتيجة الجولة |
| `LAMMA_QUICK_FILL_MS` | server | 20000 | مهلة «العب الآن» قبل ما تتعبّى الطاولة العامة بالكمبيوتر |
| `VITE_GAME_SERVER` | web | `ws(s)://<host>:2567` | عنوان سيرفر اللعب (منفصل عن الموقع) |
| `VITE_BASE` | web | `/` | مسار الأصول (`./` لنسخة تطبيق لاحقاً) |
| `VITE_ROUTER_MODE` | web | `history` | `history` = روابط `/r/CODE`؛ `hash` = `#/r/CODE` (للتطبيق لاحقاً بدون سيرفر ويب) |

انسخ `apps/web/.env.example` إلى `apps/web/.env.local` للتعديل.

**متغيرات `LAMMA_*` القصيرة للاختبار فقط.** `npm run dev:server` و`npm start` ما يضبطوا أي منها، فالتشغيل العادي يستعمل القيم الافتراضية.

## هدف النشر

**لا شيء منشور من المبرمج.** الخطة (ينفذها الـCEO): الواجهة على Vercel، وسيرفر اللعب عبر نفق cloudflared.
- `vercel.json` بجذر المشروع: يثبّت الـworkspaces، يبني `@lamma/web`، ينشر `apps/web/dist`، ويعيد كتابة كل المسارات لـ`index.html` (حتى يفتح `/r/CODE` مباشرة). اضبط بمشروع Vercel: `VITE_GAME_SERVER=wss://<عنوان النفق>`.
- سيرفر اللعب عملية Node دائمة (`npm start -w @lamma/server` أو `npx tsx apps/server/src/index.ts`) — مو Vercel serverless.
- **الـorigins:** Colyseus 0.18 يرجّع `Access-Control-Allow-Origin` = origin الطلب، واتصال WebSocket ما عليه فحص origin، يعني السيرفر يقبل أي origin (بما فيها `*.vercel.app`). تقييده لقائمة محددة مو مطبّق بعد.
- الأصول بمسار مطلق (`base: '/'`) حتى تشتغل من `/r/CODE`.
- **جديد بهالنسخة:** `apps/server/package.json` صار فيه `devDependencies` إضافيتين (`vitest`، `@colyseus/sdk`) واختبار `test` — للتطوير فقط، ما تأثر على `npm start` ولا على النشر.

## التوكن وإعادة الاتصال

- أول دخول للغرفة يعطي العميل توكن سري (`lamma:seat:<CODE>` في localStorage).
- إذا انقطع اللاعب أو حدّث الصفحة: المقعد محجوز 90 ثانية، والباقين يشوفون «بانتظار فلان… N ث». الدخول بنفس التوكن يرجّعه لنفس المقعد ونفس الورق.
- إذا ما رجع خلال المهلة: الطيار الآلي يكمل عنه للنهاية (شارة «يلعب عنه الكمبيوتر»)، ولما يرجع بالتوكن يستعيد مقعده فوراً. قبل بداية اللعب: المقعد يتحرّر.
- مؤقت لكل حركة (من سرعة الغرفة)؛ بعده حركة وحدة من الطيار الآلي. 3 مرات متتالية ← الطيار الآلي يكمل لحد ما يلمس اللاعب الشاشة أو يلعب.
- فتح نفس المقعد من تبويب ثاني ينقل الجلسة للتبويب الجديد ويغلق القديم.
- **الإخراج المحجوز:** إذا صاحب الغرفة أخرج لاعباً أثناء اللعب، اللاعب يكمل الجولة الحالية عادي، وبنهايتها يُخرج فعلياً ومقعده يروح لكمبيوتر. طلب إخراج ثانٍ لنفس اللاعب يلغي الطلب المحجوز.
